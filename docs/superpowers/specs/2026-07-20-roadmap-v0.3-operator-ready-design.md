# Design: Roadmap checkpoint — v0.2 close-out, v0.3 "Operator-ready", harness checkpoint #1 decided

Date: 2026-07-20 · Status: approved in session, pending spec review

## Context and problem

Two inputs triggered this checkpoint:

1. The **OTel trace emitter** spec (`docs/specs/otel-trace-emitter.md` on
   `feat/otel-trace-emitter`) is written and needs a milestone slot.
2. A vague goal — "get the repo to a point where it offers something palatable to

Meanwhile the ROADMAP's milestone table has drifted behind reality: v0.2 "Honest
cloud" feature scope is fully merged (A1+A2 observe-only via PR #11, B1 cache

## Decisions

### D1. Operator palatability = pitch clarity + visible payoff

Of the four candidate gaps (setup friction, visible payoff, trust signals, pitch
clarity), the ones that lose a potential operator today are **pitch clarity** (the
README doesn't land the value proposition fast enough for a stranger) and **no
visible payoff** (nothing shows an operator what Loxo is doing for them).

### D2. The payoff hook is the OTel trace waterfall

Among the candidate payoff surfaces — the A4/A5 savings + dial report, or the
per-request OTel trace waterfall — the **waterfall is the hook**: "why did this
request go cloud, where did the 800 ms go" rendered in Jaeger/Grafana, demo-able
and screenshot-able immediately, riding the already-built `Observation` seam. The
savings/dial report remains Track A roadmap work (now v0.4) and issue #6's
incentive mechanism; it is not displaced, just not the recruitment hook.

### D3. v0.2 close-out: finish all three acceptance items, then tag

v0.2 tags only after its written acceptance list is actually met:

- **Parity scorecard v1** (`docs/parity.md`) — also raw material for the pitch work.
- **Golden harness fixtures** — captured real request bodies replayed against a
  stubbed upstream (the roadmap's harness-as-spec discipline; only unit tests
  exist today).
- **Real-session acceptance check** — an OpenCode session on `loxo/*` populating
  the adequacy ledger with classified traffic and showing cache hits in `/v1/spend`.

No new features enter v0.2.

### D4. v0.3 becomes "Operator-ready"; dial machinery slides to v0.4

v0.3 is re-scoped as the recruitment release. Former v0.3 "Visible dial" content
(A4 shadow evaluation, A5 `/v1/dial`, A7 bench suite, first human-flipped
promotion) moves wholesale to v0.4; "Earned share" (A6, scorecard v2) becomes
v0.5. Track A content itself is unchanged — only its release numbers move.

### D5. Harness checkpoint #1 — decided now (2026-07-20), not at v0.3

The ROADMAP scheduled this decision for v0.3; this checkpoint took it early, on
fresh evidence.

**D5a. `/v1/messages` (Claude Code as client) enters scope — and builds in v0.3.**

Evidence weighed:

- *Terms:* Anthropic blocked **consumer OAuth tokens** (Pro/Max subscriptions)
  from third-party use in early 2026, but pointing the genuine Claude Code CLI at
  a custom `ANTHROPIC_BASE_URL` with API-key-style auth is supported — Claude Code
  natively supports third-party providers, and neither the Commercial Terms nor
  the AUP prohibit multi-model routing. Sources:
  [ToS analysis](https://autonomee.ai/blog/claude-code-terms-of-service-explained/),
  [anthropics/claude-code#5577](https://github.com/anthropics/claude-code/issues/5577),
  [y-router precedent](https://github.com/luohy15/y-router).
- *Alignment:* the excluded population (subsidized flat-rate subscribers) is
  already outside the cost win condition's stated audience — the terms boundary
  and the README's "Who this is for" boundary are the same line.
- *Demand:* Claude Code remains a top harness driving token volume on open-weight
  models ([Kimi K3](https://openrouter.ai/moonshotai/kimi-k3) at ~226B
  tokens/30d, top-15 on OpenRouter as of 2026-07-18) — the demand pattern Loxo
  would serve is mainstream.
- *Recruitment leverage:* a Messages endpoint multiplies the recruitable operator
  pool exactly when issue #6 activates. This is why it lands **in v0.3** (the
  operator release) rather than trailing at v0.4: the recruiting door opens
  widest on day one, accepted at the cost of a bigger release.

Scope boundary, written into the ROADMAP: **API-key-pattern clients only; no
consumer-OAuth workarounds, ever.**

**D5b. The Pi acceptance slot passes to Oh-My-Pi.**

[omp](https://github.com/can1357/oh-my-pi) (~12K stars, explosive growth) has the
richer request shapes — subagents, 32-tool inventories, hash-anchored edits —
that stress the classifier the way real future traffic will; Pi stays
deliberately minimal by design. Acceptance harnesses become **OpenCode + omp**,
keeping the set at two (the ROADMAP's bounded-promise principle). Existing Pi
golden fixtures are retained as informal regression fixtures with no
acceptance-run obligation.

## v0.3 scope detail

- **OTel emitter** — per the existing spec, unchanged: observe-only, `Observation`
  seam, `record(obs)` choke point fanning out to adequacy ledger + trace emitter,
  `[otel]` optional extra, fail-safe, root span + `loxo.fallback` child in v1.
- **B5 `/v1/messages` translation layer** — new Track B item. Anthropic Messages
  dialect in → internal OpenAI-compatible form → existing routing/forwarding
  untouched. Hard parts: streaming SSE event translation and tool-call mapping.
  Gets its **own spec plus golden fixtures captured from real Claude Code
  sessions before build** — same harness-as-spec discipline as OpenCode/Pi.
- **Pitch clarity** — README restructured so a stranger gets the value
  proposition in the first screen: what Loxo does, one short quickstart path
  (point OpenCode at it, first routed request), and visible-payoff artifacts up top — a Jaeger
  waterfall screenshot showing a local→cloud fallback hop, a real `/v1/spend`
  excerpt with cache stats. Scorecard v1 linked as the honesty exhibit. No
  personal/portfolio framing (public repo).
- **Onboarding polish** — whatever the quickstart walk-through reveals as
  friction, bounded by: a curious operator reaches routed traffic in minutes
  (issue #6's low-friction opt-in leg).

## Acceptance for v0.3

A stranger-shaped test, following only the README:

- (a) an operator gets OpenCode routing through Loxo in minutes;
- (b) they see a per-request trace waterfall in a local Jaeger, including a
  local→cloud fallback hop as a child span;
- (c) a real Claude Code session pointed at Loxo via `ANTHROPIC_BASE_URL`
  completes a working session on `loxo/*` tiers;
- (d) test suite green; omp acceptance session run and scored on the scorecard.
