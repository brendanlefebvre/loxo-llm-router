# v0.2.0 "Honest cloud" — Design

Approved 2026-07-18, against ROADMAP.md as adopted 2026-07-15/16 and a v0.1.2 baseline.

## Scope

The roadmap's v0.2 milestone, plus B2 pulled forward from v0.3:

- **A1** request classification (`main` / `chore` / `compaction` / `unknown`), heuristic, observe-only
- **A2** adequacy ledger (JSONL twin of the spend ledger), observe-only
- **B1** prompt-cache injection for cloud-bound requests, mechanism decided by a week-one spike (risk 2)
- **B2** reasoning support — *pulled forward from v0.3*
- **B3** model-metadata honesty in `/v1/models`
- **B4** parity scorecard v1 (`docs/parity.md`)
- Infrastructure: `LOXO_STATE_DIR` relocation, GitHub Actions CI, golden harness fixtures
- ROADMAP.md amendment recording the B2 move

**Why B2 moved:** the evidence stream (spend baseline, adequacy ledger) starts in v0.2 and must start under the final request shape — reasoning tokens are billed output and change the observable response shape, so landing B2 in v0.3 would force a re-baseline across the release boundary and taint the longest-lead-time asset the project has. Secondarily: the experience floor fails in v0.2's own acceptance test without it (cloud main turns run with reasoning off/invisible), and B1/B2 share the same cloud-bound body-mutation seam, so building them together amortizes the plumbing and the fixture assertions.

## Architecture: explicit seams (chosen over pipeline refactor / ASGI middleware)

Each feature is its own module with a pure-function seam, called explicitly from `chat_completions` — following the `config.py` precedent. The routing core (`pick_target`, `forward`), vision policy, and auth stay put.

- `classify.py` — pure: `(body, headers) → Classification(cls, signals, version)`. No I/O.
- `ledger.py` — owns `LOXO_STATE_DIR`, absorbs the spend accumulator out of `__init__.py`, adds the adequacy writer. Append-only JSONL; a ledger write failure never breaks a response (existing discipline).
- `cache.py` — pure transformer for cloud-bound bodies: `inject_cache(body, target_card) → body`.
- Reasoning injection — same seam, applied beside `inject_cache`; lives in `cache.py` or its own `reasoning.py` (decided by size at implementation time; both are pure transformers at the same call site).
- `forward()` gains an **observation record** (status, finish reason, fallback-fired, latency/TTFB, token details) filled where the SSE tee already extracts `usage.cost`, handed to `ledger.py` at response completion.

Rejected alternatives: a pipeline refactor of the handler (riskiest PR would rewrite subtle streaming semantics — pre-first-byte fallback, SSE cost tee — before any feature value ships) and ASGI-middleware observation (re-parses bodies, can't see routing decisions cleanly, awkward with streams).

## Feature designs

### A1 — classification

- Taxonomy: `main`, `chore` (title/summarize), `compaction`, `unknown`. Growing later is cheaper than shrinking.
- Signals: streaming flag, message count, tool presence/count, estimated prompt size (reuses `estimate_prompt_tokens`), system-prompt fingerprint — a small table of distinctive substrings from OpenCode/Pi title, summarize, and compaction prompts, grounded in captured fixtures rather than guessed.
- Ordered rules, first match wins, `unknown` the default. Never guess `main`: an inflated `unknown` rate is the classifier-health metric and should be visible, not laundered.
- `classifier_version` recorded in every ledger entry; bumped whenever rules change so cross-version stats never silently mix regimes.

### A2 — adequacy ledger

One metadata-only JSONL entry per `/v1/chat/completions` request, written at response completion (stream end for streaming):

```text
ts, class, classifier_version, requested_model, route (local|cloud),
served_model, reason, stream, status, latency_ms, ttfb_ms, fallback_fired,
finish_reason, had_tool_calls, tool_calls_valid_json,
tokens {prompt, completion, reasoning, cached}, usd, shadow (always false in 0.2)
```

- Collection extends the existing SSE tee: accumulate finish reason and tool-call argument fragments (validated as JSON once assembled) alongside the current `usage.cost` scan.
- `shadow` ships now so the v0.3 shadow evaluator appends to the same schema instead of migrating it.
- Never message content (roadmap risk 7).

### B1 — cache injection

- Applied to cloud-bound bodies only; mechanism per the spike.
- Eligibility from the live rate card: non-null `cache_read_per_mtok` ⇒ target supports caching; others pass through untouched.
- If manual breakpoints win: deterministic placement — end of system prompt, end of tool definitions, end of stable conversation prefix; ≤4 breakpoints; min-prefix thresholds respected.
- Client-supplied `cache_control` is never overridden.
- `/v1/spend` gains per-provider/model cache stats: cached tokens read (`prompt_tokens_details.cached_tokens`) and estimated savings vs. uncached input price.

### B2 — reasoning

- New tier field: `reasoning = "none" | "low" | "medium" | "high"` in `loxo.toml`, mapped to OpenRouter `reasoning: {effort}`; omitted when `none`/unset (current behavior stays the default).
- Injected at the same cloud-bound seam as `cache.py`.
- Client wins: client-sent `reasoning` passes through; OpenAI-style `reasoning_effort` is translated to OpenRouter's format, not dropped.
- Deltas (`delta.reasoning`) and non-stream `message.reasoning` already traverse the byte proxy; the deliverable is **verified rendering** in OpenCode and Pi, recorded in the scorecard. A harness adapter that cannot surface them → "structurally unclosable" entry with evidence.

### B3 — metadata honesty

- `/v1/models` virtual entries: `context_length` derived from the live rate card (cloud target's window for auto/cloud tiers; `local_context_limit` for local-pinned); explicit `advertised_context` in TOML becomes a manual override rather than the default source of truth.
- A `pricing` object advertises the tier's cloud-target rates as a **ceiling** (harness estimates may only err high).
- Per-call truth: cloud `usage.cost` already passes through. Local **non-streaming** responses get `usage.cost: 0` injected when a usage block is present. Local **streaming** is explicitly out of scope for 0.2.0: injecting would mean rewriting SSE chunks in flight (the router never mutates response bytes today), and local streams often carry no usage chunk at all (`stream_options.include_usage` is stripped from local-bound bodies). Consequence is mild — harness estimates err high off the ceiling; `/v1/spend` stays truthful. Noted in the scorecard.

## Testing

- **Golden harness fixtures.** Opt-in `LOXO_CAPTURE_DIR` debug flag dumps incoming request bodies (off by default; not under the state dir; documented as containing message content). One OpenCode session — plus a Pi session opportunistically — captured on the Mac, sanitized (structure kept: system prompts, tool schemas, message shapes; real code/prose stripped), pinned under `tests/fixtures/<harness>-<version>/` (a new directory; existing root-level `test_*.py` files stay where they are): main turn, title chore, summarize/compaction, tool-heavy turn. Replay via stubbed upstream (httpx `MockTransport`); assert routing decision, class label, injected fields (`cache_control`, `reasoning`, `stream_options.include_usage`), streaming/error semantics. Harness drift fails fixtures before it fails a session.
- **Unit tests.** Classifier decisions (table-driven), breakpoint placement, reasoning-injection precedence, metadata synthesis from rate cards, ledger back-compat (legacy path read, no double-count), observation-record assembly from teed streams.
- **CI.** As PR 2 above.
- **Live smoke.** `scripts/cache_spike.py` evolves into the per-milestone end-to-end check against real OpenRouter (cheap model) + local server. Manual — it spends money.

## Scorecard v1 (`docs/parity.md`)

Rows: caching, reasoning, tool fidelity, vision, metadata, streaming, error surfaces, cost — each scored Loxo vs. native stack with an evidence link (spike findings, fixture test, acceptance-session note). Standing "structurally unclosable" section seeded by whatever the spike and B2 verification surface (candidates: OpenRouter cache-affinity ceilings; harness adapters that can't render reasoning). Subscription economics (risk 1) gets a row in "collecting" status — a month of real `/v1/spend` data — not a verdict.

## Acceptance for tagging 0.2.0

1. A real OpenCode session on `loxo/*` populates `adequacy.jsonl` with classified traffic — chore and main both observed; `unknown` rate visible and sane.
2. Cache hits visible in `/v1/spend` with real observed discounts (not just injected fields).
3. `/v1/models` shows rate-card-truthful context windows and ceiling pricing.
4. Reasoning renders in OpenCode, or the gap is documented structurally unclosable with evidence.
5. Unit + fixture suites green in CI.

Pi is not in the 0.2.0 acceptance gate (its acceptance run is v0.4 per the roadmap); Pi fixtures are captured opportunistically for the classifier.

## Logistics

- Spike and development run on the droplet (needs `OPENROUTER_API_KEY`; small real spend).
- Interactive validation/acceptance sessions run on Brendan's Mac (OpenCode, MLX local server); captured artifacts (ledger files, fixture dumps) flow back for analysis.

| Decision | Choice | Alternatives considered |
|---|---|---|
| B2 timing | Pulled into 0.2.0 | Keep in v0.3 (rejected: evidence re-baseline, floor failing in v0.2 acceptance) |
| Landing strategy | Spike-first PR train | Single release branch; parallel feature branches |
| Spike traffic | Scripted on droplet, then one Mac session validates before B1 is built | Script only; real session only |
| Integration architecture | Explicit seams, pure-function modules | Pipeline refactor first; ASGI middleware observer |
| Local streaming `usage.cost: 0` | Out of scope for 0.2.0 | Mid-stream SSE rewriting (rejected: new machinery, low stakes) |
